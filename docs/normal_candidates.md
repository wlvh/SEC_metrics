# 普通保存来源候选

此开发入口从已保存的实际SEC材料自动准备输入、执行受支持的原生候选并冻结记录。它不获取新材料、不调用模型，也不修改正式结果。资料限制和程序缺口逐坐标保留；一个失败不抹掉其他成功。

```bash
python3 tools/vnext_normal_candidate.py --output-root /absolute/new/external/directory
```

默认检查十家公司当前B06/C03/C04/D01。可重复使用`--company <配置ID>`或`--metric <ID>`限定开发验证范围。输出目录必须全新、在源码外，并且不属于现有正式发布目录；已有批次不覆盖。每个坐标记录原生Run、真实期间、结果状态和错误；summary.json给出完整请求集合和实际结果。退出码0只表示所请求的候选均已生成，2表示有候选缺口，不表示Issue完整验收。

D01可通过同一Projector输出既有20字段矩阵行和18字段证据行；全部原文、换行、申报日期和字节定位保留，状态TEXT_QUAL。展示规则与执行Spec分别绑定，执行过的Spec不因新增展示列而重写。目前其余三指标的普通公共行适配仍未接入该CLI，summary中的NOT_PREPARED明确表达此限制；这不是完整发布包。

V12/issue_28_v11已产生实际冻结记录，其规则和五文件不再同版本改写；未进行正式激活。开发可以读取这些记录，但新规则扩展应使用后继版本。Marriott D01、Paramount C03已完成新进程、无Git目录的真实冷读；这种材料验收不等于39指标最终迁移或正常生产更新。后续仍需完整包、重复触发/失败保留、来源更新和旧路径退出接线。

当前不声称实时SEC最新、自动上线或正式采纳。总委托的新增费用额度和最终生产授权仍分别核对，历史关闭额度保持关闭。
