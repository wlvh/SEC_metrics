# D02 准备对照工具

`tools/compare_d02_preparation.py` 用同一份保存原件，分别以两个固定提交运行生产入口 `vnext.d02_reviewed_source.prepare_historical_legal_sources`，逐个“公司 × 财年”比较 D02 准备的状态与内容。它离线运行（工作进程禁止网络），不调用 SEC 或模型，不写来源目录。

## 什么时候运行

- 改动 D02 共用准备路径时运行，包括附注定位与归属、页眉选择、Item 8 请求构造和文本覆盖。
- 不影响这些路径的小修补，只跑定向测试，不必每个提交都跑全套原件。

## 命令

PR 的 head 已经包含当前 main 时，直接对照 main 与 PR head；两个提交都在仓库里，别人可以复查或重跑：

```text
git fetch origin main pull/<N>/head:pr-<N>
python3 tools/compare_d02_preparation.py --baseline origin/main --candidate pr-<N> \
  --source-root <保存来源根> --output-dir <尚不存在的新目录> --fail-on OK_TO_FAIL
```

PR 还没接入当前 main 时，先在本地合成“main + PR”。这个合成提交只在本机，`manifest.json` 会记下它的两个父提交和树哈希，别人可以用 `git merge-tree --write-tree <父1> <父2>` 重建同一棵树并核对哈希：

```text
T=$(git merge-tree --write-tree origin/main pr-<N>)     # 有冲突时退出非零，需先解决冲突
C=$(git commit-tree -p origin/main -p pr-<N> -m "local combination" "$T")
python3 tools/compare_d02_preparation.py --baseline origin/main --candidate "$C" ...
```

其他参数：
- `--companies`：默认是对照版本注册表里的全部公司；只给一部分时，结果会标明“部分范围”。所给公司必须出现在任一版本的注册表中，为空或有重复都直接报错。
- `--fiscal-years`：默认 `2021-2025`。
- `--jobs`：默认 4，是两个版本合计同时运行的工作进程数。每个样本单独一个进程，一个样本崩溃或卡住只影响它自己。
- `--timeout-per-sample`：默认 600 秒，限制单个样本；超时的样本记为未比到。
- `--keep-code`：保留两个临时工作树。

单个样本多数在 30 秒内，最慢的 JPMorgan 约 1.5–3 分钟；10 家公司 × 5 年，4 个进程大约 13 分钟。

## 输出

输出目录下有三个文件：
- `summary.md`：结论和逐样本变化。
- `comparison.json`：逐样本明细。
- `manifest.json`：两个提交及其树哈希、工具文件的 SHA-256（`tool_sha256`）、来源根在运行前后的文件摘要与目录摘要、样本范围、Python 与平台信息、每个工作进程的退出情况。

| 类别 | 含义 |
|---|---|
| `SAME_OK` | 两边都准备成功，比较的内容完全相同 |
| `CHANGED_OK` | 两边都成功但内容不同，并写明不同之处；`request_id` 变化表示已保存的模型回答不再适用 |
| `FAIL_TO_OK` / `OK_TO_FAIL` | 状态变化 |
| `SAME_FAIL` / `CHANGED_FAIL` | 两边都失败（例如缺原件、规则拒绝）；这些样本**未被验证**，单独列出原因 |
| `NOT_COMPARED` | 没有结果，或工具自身出错 |

以下任一情形都会让结论标为 INCOMPLETE（退出码 2）：
- 有样本没有比到；
- 工作进程失败或超时；
- 来源根在运行中发生变化，包括文件内容改动、新增或删除文件和目录；
- 代码工作树被改动，或其中出现任何新文件（包括未跟踪或被忽略的文件；工作进程不写字节码文件）。

结论完整时退出码为 0；完整但出现 `--fail-on` 中列出的类别时，退出码为 1。

## 比较了什么

逐样本比较以下内容：
- 选中的年报与计算目标：accession、期间、原件哈希，以及 D02 的范围定义（`scope`、`scope_key`）；
- 来源核验记录；
- 每份文档的覆盖状态与原因；
- 附注引用及其范围、检查范围；
- D02 候选的段落和标签，以及完整候选记录（正文和原件位置：字节范围、片段哈希、原件与文档编号）；
- 附注提案与文档的编号；
- 页眉删除的段落；
- D03 摘要和其余字段；
- 每个 Item 8 请求的编号、段落集合、必须判断的段落、正文摘要，以及请求的其余全部字段（指令、回答格式、年报、公司与目标身份）。

此外，整份准备结果按部分各算一个摘要（顶层每一项，以及其中每个键）。上面没有单列的字段发生变化，也会判为内容不同，并列出变化所在的部分，例如 `period_selection.policy_id`。

## 限制

- 只覆盖 D02 准备，不含 D03 结果、模型回答的应用、公司全链和 CSV。
- 样本只取注册公司。原件目录里为其他用途保存、但不在注册表中的文档，不在比较范围内。
- 结果依赖所用的保存来源根。双方应核对 `manifest.json` 里的来源根哈希一致；历史来源可按 #52 的 `evidence/issue47_acquired` 离线恢复。
- 工具不能阻止被测代码写入来源根，只在运行后比对哈希，发现改动即判为不完整。请对可恢复的副本运行（例如按 #52 恢复的目录）。
- 两个工作树建在输出目录下，运行结束后删除；运行被中断时，用 `git worktree prune` 清理。
