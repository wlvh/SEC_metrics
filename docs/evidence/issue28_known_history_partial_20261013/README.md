# Historical mixed scope preserves supported neighbours

The historical wrapper previously required every requested metric to have a
received factory before calling the existing company controller. A defined
but unfinished metric therefore prevented even a supported neighbour from
being processed or reused. The peer's actual existing-task counterexample was
read at fixed `57b218b6ffc67ca1a6d6bdbf711ebb5c289d136a`,
`docs/evidence/issue47_history_mixed_scope_20261013/{README.md,actual.json}`;
this author did not write to that peer task.

This finite change separates the project's valid metric IDs from received
historical factories. `company_local._run_saved_history` validates known,
unique, nonempty IDs, then supplies factories and processing files only for
received metrics. It still sends the entire requested scope to the existing
controller, which already records
`PROCESSING_INPUT_OR_IMPLEMENTATION_REQUIRED` for missing interfaces. No
factory, Result, numeric zero, structural N/A or disclosure-absence conclusion
is manufactured for the unimplemented metric. Unknown/duplicate/empty IDs and
the existing D04 saved-package prerequisite remain rejected before processing.
No new controller, state schema, model chain or source acquisition is added.
