# D03 原始响应录制保存与冷读

现有已审`regulatory_fact_review.py`能从保存原件重建候选并校验模型式响应，返回解析对象和原始字节SHA，但明确声明**没有另存原响应字节**。本次新增的`d03_recorded_response_store.py`仅补这一条离线证据链：从当前保存来源重建原请求与显式后继请求，先执行既有来源/语义检查，再把实际传入的`raw_response`字节、来源、前后请求和检查结果分别以不可变文件保存，最后写带文件SHA/size和模块身份的包索引。独立读取先核验文件、只读重建来源及请求，再对保存的原响应字节重新运行同一检查。若中断未写索引、原字节改动、把录制信用重签为LIVE或路径指向原真实调用账本，均不得读成完成。

最终代码下`recorded-store-final.log`以真实保存的JPMorgan D03来源和**合成录制响应**运行2项正反测试，通过116.887秒。原响应含非规范JSON排版和`U+037E`，存储与读回逐字节一致；未决没有被改成确定的当前调查结论。`/private/tmp/issue28-d03-recorded-packet-20260927-02`保存测试时复制的有效包，`cold-read-final.log`从另一进程禁网、禁子进程完成来源和响应重验，结果仍为2个未决，详见`summary.json`。测试发生在提交前的工作树，`summary.json`记录模块SHA；提交后仍须按确切差异核对，不能把本地通过自动写成远端CI或独审。

该包只有`RECORDED_TEST_ONLY`开发证据，没有真实provider回应身份、原生Evidence/Result/Run或公司D03结果；不提供真实调用入口，也不改变旧D03请求、旧来源事实错误审阅或任何已推送需求绑定。原真实账本仍止于第194槽，provider/paid/SEC为143/143/51，新增调用0/0/0。下一步是把已验证原响应保存职责接入未来**获授权**的D03请求/持久化/原生链，验证全文覆盖、冲突和业务判断；D03真实请求与资源决定仍单独保留。没有新tar.xz、MANIFEST重生成、生产权限或#47操作。
