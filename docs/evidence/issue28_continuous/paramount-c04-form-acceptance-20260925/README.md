# Paramount C04：保存来源的申报形式接受边界

本次直接复用原账本SEC第105—108次及已保存的其他四份普通8-K来源；`probe_saved_forms.py`在原安装根只读执行，没有SEC或模型调用。先用当前保存的CIK2041610 submissions原文字节哈希，核对旧发现材料中的元数据身份；随后逐份重读6个申报的primary/header请求证明，并核对header `<TYPE>`与submissions里的原形式相同。第171次等B13账本材料和#47来源均不参与。

现有通用`source_set_manifest`与`adapt_8k_item_index`在**明确传入**`8-K`、`8-K/A`、`8-K12B`、`8-K12B/A`四种形式时，能用同一完整保存清单接受当前财年的6份本注册人申报、12份原生来源引用，形成22个来源绑定的Item简述候选；其中没有`4.01`候选。删除一份申报会被完整清单校验拒绝，拿旧两种形式清单冒充六份也被拒绝。具体accession、原文件哈希、请求尝试、Item码及返回的manifest身份见`summary.json`，命令结果见`probe.log`。

这说明通用Item适配器**本身**无需为8-K12B另建解析器；当前普通C04 v2的`normal_governance_input`仍只选择8-K/8-K/A，其Spec与resolver也只接受这两种形式。新四形式来源集合没有进入普通C04原生Run，不改变旧Spec或结果。下一项技术工作是显式后继形式选择、当期/修订/历史清单同范围绑定及原生Run输入；默认接口保持旧行为，不能悄悄拓宽#47依赖的共享默认。

22个Item简述中没有`4.01`**不是**审计师没有变更的业务结论。Paramount当前没有同CIK前期10-K可作原定义的前后审计师比较；EY文本归属Skydance Media LLC，PwC命中是董事履历，不能跨主体补齐事实。是否允许另一条有充分原件依据的否定路径仍是业务规则决定；本次没有给C04的0/1、没有正式Result/Run、没有生产发布信用。总账本轮仍为143/143/49，D03仍未调用。
