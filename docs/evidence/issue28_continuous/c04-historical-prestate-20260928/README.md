# C04受限续接：已有B01历史指针但本轮未尝试

已确认的缺口是：普通更新状态根含上次B01成功`current.json`与尝试目录时，本轮首次SEC来源捕获成功、处理副本却在创建阶段失败，前次报告中的B01为`UPDATE_BLOCKED`且本轮没有新尝试。旧续接谓词只接受无`current.json`、无尝试目录的根，故即使历史B01指针有效也无法继续获取第二份C04来源。仅凭报告声称“未尝试”又不能放行，因为可把本轮真实B01成功行降格为`UPDATE_BLOCKED`。

本次只为**显式C04混合路线**增加捕获前状态指纹。当前请求控制器在申领SEC槽前只读普通指标状态根的配置、当前指针、尝试目录名称与intent/terminal字节身份，把指纹写入该次`sec-plan.json`，不写入业务请求摘要；原账本的`intent.plan_id`及终态`evidence`共同封存计划字节。下一轮续接若报告声称B01本轮未尝试、磁盘却有历史指针，就要求B01状态文件与捕获前计划中登记的指纹相同，再由既有配置和当前指针检查核对；新尝试、指针改动或身份不一致均在第二次捕获前拒绝。旧计划没有该字段时仍按旧保守谓词读取。普通`capture()`新增的两个可选参数默认均为`None`，非C04来源不能携带此状态；默认SEC请求计划不新增字段。
