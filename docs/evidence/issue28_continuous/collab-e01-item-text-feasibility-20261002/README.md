# E01：在本方十家公司保存8-K上核对可读取条目正文

`measure.py`固定读取 #47 已提交的纯来源读取器 `historical_event_items.py`，源码提交 `488a6173`、Git blob `ff6996d2…`。它只把该固定源码在临时模块中运行 `item_text()`，**没有把#47历史分支代码、快照或运行根接入PR43**。每条输入来自 #28 旧普通 E01 Run 已登记的 8-K 主文件 SourceReference 和 RawBlob；脚本先重验主文件完整 SHA-256、长度及申报身份，再对已批准候选代码 1.01／2.01／8.01 调用读取器，保存条目起止、正文摘要、哈希和失败原因。首次脚本误以为所有私有状态根都有公司名子目录，在 Marriott 提前退出；`measure.log`留存，修正证据脚本路径后 `measure-repair.log`通过，未修改产品代码或原件。

十家公司保存来源共 **60个候选条目，60个能机械定位原文、0个被该读取器拒绝**。Ford 的并列 1.01／2.03 标题被明确记为共享正文；Pfizer 报告 Metsera 收购的 8.01 读到正文，未再只看由程序生成的头文件说明句。Enphase 在此候选代码集合里为0条。`measure.json`保存逐公司、逐条目来源身份、读取跨度及SHA，但**这不是60条并购判断**：来源都能读取，不等于分类、主体、期间、重复交易或完整结果正确。最大的单项正文36,041字符，Paramount 14条合计83,432字符、Lumen 15条合计71,372字符；这只是字符负担，尚未证明请求token、4096输出或真实模型表现。

现有 Pfizer 假零与四家公司 1.01 融资误计的旧 Result 继续扣留。E01 的计数单位与去重细节仍须按已有决定和合同最终对齐；本轮不引入提供方的“每个条目计一次”作为本方未决定政策，也不改冻结路由/旧Run。真正的后继仍需把这些条目正文、来源身份、内容判断、未决、去重和原生Result/Run接通，并按获准调用范围验收。没有新 Result、完整公司、390或生产信用，真实provider/paid/SEC新增0/0/0。
