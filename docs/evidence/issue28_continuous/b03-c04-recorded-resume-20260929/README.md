# Salesforce B03 historical no-credit state through C04 two-source recovery

This is a bounded **recorded-only** integration check of the `81b927c` B03/C04 recovery seam. It uses the original #28 saved Salesforce bodies and logged SHA-256 values, the existing SEC acquisition controller in `RECORDED_TEST_ONLY` mode, the ordinary B03/C04 update controllers, and an independent-process installed Run replay. No provider, paid or real SEC call was made. It does not create a corrected B03 amount or a new fully completed company.

The repository baseline source root cannot prepare this C04 input, whereas the #28 cumulative source root can. `probe.py` compared their authenticated governance-input source proofs: eight URLs differ. It verified each response against the original #28 source log. In a fresh recorded ledger, two of these URLs required recorded captures (Salesforce FY2025 primary and one 8-K header); the other six were already verified in the baseline and returned `EXISTING_VERIFIED_SOURCE_REUSED`. The resulting recorded root had 31 source proofs and C04 `PREPARED`. The eight URLs and their individual recorded/reused dispositions are in `run-v4.log`. This did not borrow #47 sources or its acquisition authority.

The unchanged old ordinary controller then created a historical Salesforce FY2026 B03 `CANDIDATE_READY` record. Its old terminal and successful pointer remain, but the current source-scope guard denies it present business credit because the selected 1.2 billion USD D&A source is fixed-asset-only. To exercise the mixed stale-root path, the probe changed only three **recorded test-root rule copies** into a historical processing state, as the existing C04 mixed-source material test does; the current processing snapshot was rebuilt from bound #28 rules. The original cumulative source root and live ledger were not changed.

With `max_sec_requests=1`, the first ordinary refresh recorded the saved submissions response: C04 `CANDIDATE_READY`, B03 `PREVIOUS_INPUT_WITHHELD`, old B03 success pointer unchanged and no current B03 candidate; source refresh was `REFRESH_INCOMPLETE`. A forged prior report claiming a nonempty current B03 candidate was rejected with `ORDINARY_REFRESH_RESUME_OTHER_METRIC_CHANGED` **before** another recorded capture. The valid `resume_from` then recorded the saved Company Facts response: source refresh became `REFRESH_CHECK_COMPLETED`, C04 returned `NO_SOURCE_CONTENT_CHANGE` with the same successful candidate, and B03 remained `PREVIOUS_INPUT_WITHHELD` with no current credit. Overall `UPDATES_INCOMPLETE` is correct because B03 still lacks a valid current result; it is not recast as a successful two-metric company update.

`cold.py` ran in another Python process with socket, DNS and HTTP disabled. It mechanically replayed the installed historical B03 Run, confirmed the current B03 scope conflict, then replayed C04 as `PUBLISHED/0` with Result ID `sha256:0737cedcf59d2c009f2395268f9d517b8fe8e88d1690d5a4bc99a1de40a6622e`. The selected request log and both mutable current-pointer files had identical SHA-256 before and after that cold read. `result.json`, `run-v4.log`, `cold.log` and `run-v4.exit=0` retain the successful observations. The original actual #28 ledger was read after the test: 195 claims, cumulative provider/paid/SEC `143/143/52`, unchanged from the last recorded count; the recorded test ledger used four simulated SEC slots and zero real calls.

The first two probe attempts failed due to assumptions in the **test script**, not a product assertion: `run.log` tried to read an ordinal from the SEC terminal instead of the receipt's row index; `run-v2.log` treated an already verified baseline source as a new capture. `run-v3.log` passed the two-source path without the later negative and cold-read checks. Those attempts and their exit files remain separate, not relabelled as the final run.

This closes the specific previously unexecuted B03/C04 recorded combination and its durable readback. It does not prove an authentic later new filing arriving online, Salesforce's correct B03 EBITDA rate, the other 389 current coordinates, full 39-metric automatic update, formal publication, or old semantic entrypoint retirement. No production pointer, #47 branch/worktree/ledger/snapshot or historical result was operated.
