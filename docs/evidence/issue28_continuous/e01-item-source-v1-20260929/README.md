# E01 opt-in source binding for an 8-K Item 8.01 section

The current E01 catalog asks for `merger`, `acquisition`, `combine` or `transaction` in an Item 8.01 brief, but a header-listed 8.01 gets only the synthetic `8-K item 8.01 parsed from hdr.sgml`. The existing repository fixture proves a primary body containing “acquisition transaction” is missed by that path; the [source audit](../e01-southwest-source-scope-20260929/README.md) separately proves Southwest's two direct Item 1.01 counts refer to non-M&A subjects. The **business meaning of E01 remains undecided**.

`scripts/vnext/e01_item_source.py` is an **opt-in source component** for that missing 8.01 body. Given an existing verified header claim, its original primary SourceReference and original bytes, it checks exact raw-byte identity, company, accession, source role and claim-to-primary link. The first version (`7d0f7a69`) was independently reviewed as [NEEDS_FIX](independent-review/conclusion.md): a body cross-reference to Item 9.01 could truncate the section, and hidden HTML could be accepted as visible text. That verdict remains the history of the original patch.

The repair parses the authenticated HTML into text and structural blocks. It accepts a unique 8.01 heading and a matching 9.01 or `SIGNATURES` boundary only when their block structure supports a heading; body cross-references cannot silently end a section. It skips explicit non-display subtrees (`script`, `style`, `hidden`, `display:none`, etc.) and declines documents with CSS stylesheets whose visibility it cannot establish. A competing structured heading, duplicate boundary, empty section, changed source bytes, wrong claim or changed saved section fails closed. This is a bounded DOM-level visibility check, not proof of every browser rendering rule or every possible 8-K layout. `verify_bound_801_primary_section()` rebuilds saved section data from the same original inputs before reuse. Character offsets belong to the normalized accepted text, not raw HTML byte offsets; the separate raw asset hash preserves original-byte provenance.

The new function **does not match an E01 event, change the frozen event adapter or catalog, create a Result/Run, or grant source acquisition credit**. The existing `deterministic_router.py`, `normal_zero_ai_results.py`, `catalog/event_routes.json`, V13 and V14 manifest bytes are unchanged relative to `237c7cf4`; `scope.json` records their SHA-256 values and that only one fast selector was appended. `check-binding.py` confirms the current V14 execution/semantic bindings and offline provider receipt still validate, while explicitly recording that the new module is **not in the current runtime authority**. Thus no old request, claim, Result or current E01 business output was re-signed. A later explicit V14 successor must integrate and review this source content before it can affect event matching.

The repair's directed tests passed **4/4**: authenticated binding and saved-section reconstruction; complete output despite body cross-references; competing heading and ambiguous duplicate rejection; explicit hidden content and uncertain CSS rejection. The fast suite passed **142/142 selectors** in 94.376 seconds (`repair-fast.log`), and V14 execution/semantic/provider bindings still validate (`repair-binding.log`). `probe_801_source.py` applied the repaired module to Southwest's saved debt-offering 8-K: it preserved the old 8.01 claim ID and bound a 174-character section, excluding the actual Item 9.01 heading, without classifying or changing a metric (`repair-probe.log`). The private source installation is local, so this is not an independent portable company Run. The previous directed/fast/binding logs remain evidence for the original reviewed patch, not the repair.

This is a necessary original-text transport step, **not a completed E01 fix**. In particular it does not decide whether Item 1.01/2.01 alone count, prove current 8.01 M&A recall, audit the remaining E01 positive filings, complete Southwest's 39 metrics, or change production. A source-code limited independent review of the repair SHA is still required; parent-run tests are not that review. No model/SEC calls or #47 branch, ledger, snapshot or PR operations occurred.
