# B03: repair a current update after an old successful Run loses current credit

The preceding `74c36fbc` source check correctly withholds Salesforce FY2026 B03: the selected 1.2 billion USD depreciation-and-amortization fact is explicitly limited to fixed assets. A later ordinary update, however, verified the historical `successful_attempt` with the new rule **before inspecting the new source**. Its known scope conflict raised immediately. A later corrected filing could therefore never start a new B03 attempt. The old Result/Run and historical `SUCCEEDED` status remain valid as history, but do not grant current B03 credit.

The explicit V14 B03 successor now distinguishes a mechanically valid old success with this exact source-scope conflict from other verification failures. Reconciliation of an interrupted historical terminal may preserve that terminal; it still requires mechanical Run/row/source verification. Ordinary execution rechecks the previous success and gives it no `last_verified_candidate` credit when the scope conflicts. The same input records `PREVIOUS_INPUT_WITHHELD`, never `NO_SOURCE_CONTENT_CHANGE` or a new successful Run. A changed input is allowed to start a fresh attempt, keeping the old pointer and predecessor link until a new Run passes the full current source guard. Source tampering, changed rows, invalid identities and unrelated exceptions still stop. No history is deleted or rewritten.

This does **not** prove that a corrected Salesforce filing has been obtained or that its B03 will succeed.
