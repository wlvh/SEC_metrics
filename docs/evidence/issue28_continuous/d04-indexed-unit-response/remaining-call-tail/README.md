### 固定来源根的旧处理规则边界

只读测量时，固定根的`ordinary_public_projection_v1.json`仍为旧SHA `56d4191d…`，当前仓库为`f88cb122…`。根任务此前新刷新入口在复制处理规则时被`Immutable receipt bytes differ`拒绝，发生在SEC外发之前。这个失败不是来源缺失，本发现结果也不等于初始化成功。

## 不随根任务进行中的调用变旧的计算式

当前基数为D04 93 + B13 17 + D03 proposal 130 = **240个基础请求组**。以原71结束时为锚点：已计provider/paid36，当前基础任务中有效且保留的原70为1组。此后：

- `Δp`：固定账本新增provider/paid额度消耗，包含成功、失败、诊断以及按规则占用额度的UNKNOWN，不能只计成功；它不表示检查了账户金额。
- `Δs`：基础任务中新完成且原身份/当前检查有效的唯一请求组数；旧失败、重复执行、历史诊断不计。D03若未来取得proposal响应，只表示该基础步骤，不表示完整指标。
- 已知基础剩余：`239−Δs`。
- 原provider/paid余量：`204−Δp`。
- 当前基础方案已测资源缺口：`max(0, 35+Δp−Δs)`。

完整计划还须加上尚未执行、经实际证据确认需要的`V_remaining`（D03独立验证）、`U_remaining`（变化输入的额外模型任务）和`A_remaining`（确实不同请求的最终验收任务）。替代一个未完成基础组的修后请求已经在基础剩余里，不重复加一次“reserve”。尚未测定的项保留变量，不编造固定额度。

更新或最终验收若保持**同一原始请求**，且原收据和当前检查都满足，可合法复验，新增模型调用0；变化输入、提示或输出合同另计。隔离发布、回退/恢复和旧入口退出准备不因本材料新增模型/SEC调用。

SEC按独立累计量计算：若当前已计SEC为`C_sec(t)`，可用额为`80−C_sec(t)`；固定当前图的已知待刷新为`29−m(t)`，另加刷新后实际新发现的必需地址。原35次时有45次余量，29个已知元数据节点在该额度内；剩余16不是为未知情况作出的保证或自动预留。

这些是当前实现/固定来源图的实测条件，不是所有可能设计的理论最小调用数。代表验证结果、D03完整路径和来源刷新结果得到后，用同一总账集中决定实际差额；不重复申请原预算，不超额，不缩掉最终目标。
