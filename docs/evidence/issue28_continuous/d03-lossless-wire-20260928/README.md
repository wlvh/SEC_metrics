# D03 current request preserves original source bytes

The D03 source assembler uses the same complete annual source units as D04, but its current request factory had still used the canonical JSON serializer. That serializer normalizes `U+037E` to an ASCII semicolon. The already saved Paramount source contains four such characters. Before this change, D03 source and request files could silently lose those four original characters even though their semantic IDs remained stable. This is a pre-execution representation defect, not a model classification issue.

This patch includes D03 in the existing lossless source/request/wire serializer and in the source-unit byte check. It does not alter `canonical.py`, the semantic hash algorithm, the D03 policy text, the fixed 4096 output limit, old D03 recorded packets, or the D03 execution prohibition. D03 requests remain `replay_only`; no provider or SEC request is made. B13/D04 serializer selection is unchanged. Only the unfrozen V14 bindings and their three current wiring receipts are refreshed; V13 and historical installed packages retain their original identity.

`validate_actual.py` used the original saved Paramount input with network/DNS blocked. The current factory produced 14 groups and 51 source units; the source, selected request and would-be HTTP body each retained the same four `U+037E` characters. The selected request's measured input was 194,092 tokens, within the current 200,000 context limit. Replacing its source file with the former lossy serialization was rejected before claim. This is an actual-source representation check, not a model response, provider execution, Candidate/Evidence, or company result. Its result is in `actual.log`.

`unit.log` records five focused tests including D03 source/request/wire byte preservation and lossy input rejection. `compat.log` records the existing saved-source D04 mock opener/controller test and the D03 successor partition negative test. `rebind.py`, `binding.log` and `binding.json` record the exact old/new execution file identity, current V14 closure, rule validation and provider/SEC/ordinary-refresh wiring receipt checks. `fast.log` and `fast.exit` record one fixed-tree fast run. Earlier long JPMorgan packet/cold-read and D04 runs were not repeated.

The bounded next D03 work is the native Candidate/Evidence/Review/Result/Run path with real execution identity and full group semantics. This patch does not claim that path or D03 real-call permission. Current ledger totals are unchanged at provider/paid/SEC 143/143/52; original failures and successful D04 candidates are unchanged.
