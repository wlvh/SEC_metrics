# 混合C04中新年报主文件的有限来源启动

上一段混合来源过滤要求先成功构造完整C04 case；新财年10-K主文件尚未取得时，普通年报准备会报`SAVED_SOURCE_MISSING:<URL>`，即使已验证的发行人submissions清单已经给出该URL，也无法进入SEC获取。当前增量只补**这一种**缺件：从已验证的本CIK submissions及其已校验申报行重建当期10-K/10-K/A主文件URL，且只有实际准备错误精确等于该URL的`SAVED_SOURCE_MISSING`、发现项角色恰为`current_annual_primary`及状态为`MISSING_SAVED_SOURCE`时，混合C04来源模式才可选择它。受控SEC获取器在真实使用时仍会持原账本锁重新发现并校验声明、官方URL与调用额度。其他缺件、代理来源、错误主体、不同URL和任意解析/身份冲突不得借此通过。

`fast-bootstrap.log`的3项禁网/模拟检查通过：已验证submissions可指定唯一缺失年报主文件；无证明、代理角色或URL不一致拒绝；协调器在C04 case暂时不可构造时只把该年报URL交给**模拟**source-only捕获，非缺件错误没有捕获。模拟录制账本保持零槽，真实模型/SEC调用0/0/0。测试未构造尚不存在的新财年真实年报，也没有验证获取后直至公司Result/Run的完整新财报自动更新。当前保存来源的混合两条录制SEC来源和旧C04-only续接实现主路径未改，原365.477秒/330.682秒日志按精确前驱范围复用，不重复收费或重跑。

本次只改变未冻结V14协调器和其当前执行绑定；V13普通身份不动。最终代码根、原安装数据根、当前provider/SEC/刷新收据见`binding-current.log`。第193—194槽原真实获取与已发布候选身份保持；本次没有新公司结果、无生产操作或#47/PR52动作。下一步须在真实新财报到来或有原件可核对的录制新年场景，验证后续依赖发现、来源获取、原生Run和失败恢复；本增量不是“新财年自动更新已完成”。
