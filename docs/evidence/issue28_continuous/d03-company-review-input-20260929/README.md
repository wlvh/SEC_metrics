# D03 complete recorded groups enter a pending company ReviewUnit

The existing D03 collector replayed each saved Candidate/Evidence but stopped before a company-level Review. The explicit `include_company_review=True` path now takes its **complete** recorded set, binds every group receipt and the full saved-source units into one pending ReviewUnit, and retains each unresolved group. Missing or failed groups cannot enter this path. The default collector return is unchanged.

This is a recorded, synthetic-response exercise. The company Candidate and Evidence certify receipt and source coverage only. The ReviewUnit has no decision; it is ineligible for SYSTEM approval, and no Result, Run, public row, real model request, SEC request or production credit is created. A model-shaped “current action” in the fixture remains a proposal, not a true finding about Marriott. The next native step must supply actual provider-bound responses, a substantive company Review that resolves cross-group subject/status/date conflicts, and a Result/Run route that independently replays the complete source and decision. A zero-finding set cannot become “no investigation disclosed” without the separately approved absence rule.

The new helper uses the existing `OBSERVATION_CANDIDATE`, `EVIDENCE_CHECK` and `REVIEW_UNIT` records. Its review context binds every original source unit by hash, raw-source proof and ordered ID, and includes the per-request accepted findings and quotations. It does not copy the full roughly 2.5 MB Marriott source into each review asset; the original remains available from the authenticated source paths. It rechecks the complete set ID, source ID, company/period, each response digest and every group Candidate/Evidence before creating the unit. It does not change the frozen ordinary Run defaults or install a new persistent review database. `rebind.py` and `rebind-followup.py` update only the unfrozen V14 execution hash for `d03_native_assessment.py` and the three current wiring receipts; V13 bytes remain unchanged. The exact final V14 closure is in `binding-final.log`.
