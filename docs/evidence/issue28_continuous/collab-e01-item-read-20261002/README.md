# E01：让显式来源读取器实际读到 Pfizer 8.01 正文

[前一份本方原件审计](../collab-e01-pfizer-20261002/README.md)已确定：Pfizer FY2025旧E01零值的Run保存了 2025-11-13 的8.01头文件和主文件，冻结路由却把程序自写的`8-K item 8.01 parsed from hdr.sgml`当作正文匹配。旧精确Result已扣留，原件和失败保留。本补丁修复已有的**显式、仅用于来源准备**组件 `e01_item_source.py`：普通可见的黑色文字与相对定位不再被当成“可见性无法证明”；透明、零字号、低不透明度、远离页面及其它无法证明的样式仍拒绝。Item 8.01 由来源中的条目代码定位，不要求其标题恰好只写“Other Events”；带链接的目录条目不能冒充正文标题。

最终源码在已保存 Pfizer 原件上生成来源绑定记录 `E01_VERIFIED_PRIMARY_ITEM_801_SECTION_V1`。`verify_pfizer.py`从 #28 旧Run的8.01 claim、同一主文件SourceReference与资产哈希重建可见范围，读到“Pfizer … completed … acquisition of Metsera, Inc.”及合并协议；身份与正文重读一致，改坏原件或改坏保存节段均拒绝。`pfizer-section.json`仅保存局部摘录和来源身份，不构造或批准新的E01数值。定向单测最终树6/6通过，涵盖实际原件、非标准8.01标题、目录伪标题、正常可见样式和隐藏反例。

本组件尚未进入普通E01 Run或V13/V14执行规则文件集合；冻结路由、旧Spec/Run/Result不动，无绑定重签。要达到已决的“经内容确认的并购公告”目标，还需要完整候选条目范围、交易主体及语义确认、1.01借款协议排除、申报/事件去重和统一原生链。仅能读取Pfizer一份原件不代表十家公司召回或正确计数。修补后的真实模型/SEC调用均为0，旧可信统计仍扣留13坐标／19精确身份，生产权限不变。

本目录有一次本地fast-suite探索运行：它开始后源码又增加了目录链接负例保护，故不能把其完成状态当作**最终源码树**的145项验证；最终源码的定向6项与保存原件绑定脚本已重新执行。远端CI及限定独审另按实际提交身份登记。
