# D03 recorded native request unit

This is a bounded step toward D03's native company result. The current saved-source factory supplies a complete set of D03 request groups, but previously none could acquire a source-bound WB-3 Candidate/Evidence receipt. The explicit `execute_d03_recorded_assessment()` path now accepts only a recorded ledger, a recorded wire response and a replay-only current-source request. Live D03 remains closed, and the default feasibility entry still rejects replay-only successors. The existing controller records the source, request, raw wire, plan, terminal and native acceptance under their own identities. `replay_native_response()` rechecks a successful recorded request from disk.

`d03_native_assessment.py` uses the current D03 response checker and, for an old source-fact group, rebuilds the source-anchored successor and its candidate reviews from the original source. The development D03 Spec binds the assessment's text scope without defining an absence result. A per-request Candidate/Evidence means only that this request has a complete, reference-valid recorded answer; it does not establish the truth of a model classification or a whole-company D03 Result/Run. Explicit unresolved answers fail. Background and reported-process findings can retain unknown subject or timing without being misrepresented as confirmed current action.

The new recorded path has no real provider or SEC calls, no old-failure upgrade, no whole-company result, and no production permission. The historical canonical hash algorithm and V13 identity remain untouched. Existing B13/D04 native behavior and shared default signatures are intended to remain unchanged; this is checked by directed tests and current V14 binding/wiring. D03 real execution still requires separate source/Review integration and resource authority.

`native-test-initial.log` records the first Marriott saved-source positive and unresolved negative under the initial recorded plan. After the D03-only Evidence check name and the recorded-ledger root guard were made explicit, `native-test.log` records the final Marriott directed set: three tests passed in 31.870 seconds. It includes source-fact-candidate digest identity and a preclaim refusal when a test ledger's root is replaced with the real budget root. `compat.log` records B13 native acceptance and the existing readback path, 2/2 passed in 26.813 seconds after the Evidence-name change. `regulatory-compat.log` records the original public D03 source-fact checker, 2/2 passed in 69.100 seconds before the Evidence-name and ledger-guard changes; neither touches that public checker. `binding.log` and `binding.json` verify the final V14 file set, semantic rules and provider/SEC/ordinary-refresh receipts against the pushed parent `29b401d7`. The real ledger still has 195 claims: provider 143, SEC 52. The paid count remains 143 under the existing policy.

The saved JPMorgan old-fact group is a necessary second shape. One synthetic recorded response addressed its one anchored candidate and 33 required references. The controller produced one recorded Candidate/Evidence; `response_check` retained `source_fact_current_status_proven_by_program=False`, and a separate disk replay revalidated it. The synthetic answer deliberately exercises the current-action response branch; **it is not independent evidence that JPMorgan disclosed a current investigation**. No D03 company Result or public row was created. The first complete recorded/cold-read test took 653.731 seconds. Reusing the existing immutable request-construction scope and removing repeated source authentication inside one already validated recorded operation reduced it to 294.797 seconds. Sharing only that scope across preparation and execution, while opening a new scope for replay, reduced the final measured test to 248.022 seconds (factory 86.728, recorded execution 80.790, separate replay 80.477). Earlier intermediate logs remain in this directory. The final anchor test still exceeds the source suite's default 240-second single-case limit, so it remains a locally executed material test instead of being added to the normal CI selector list. Raising the limit merely to include it would not improve the business path.

`tools/run_fast_tests_v2.py` adds only the Marriott recorded native selector at the end of the source-material list. A single full retry passed **135/135** in 307.920 seconds; the initial failure remains in `fast-first-failure.log`, and the successful result is in `fast.log`/`fast.exit`. The fast run preceded only a D03-specific Evidence check name adjustment and a recorded-ledger preclaim guard; the affected Marriott test was rerun on the final code, and B13 replay/acceptance was rerun after the Evidence-name change. No timeout or selector implementation was changed. Existing long D03 packet/cold-read and D04 company material were not repeated. The [exact `e1865d7e` limited independent review](independent-review/conclusion.md) returned `PASS_WITH_BOUNDS` after 44 cumulative tool calls. It independently reran the 3 short D03 tests and saved the raw log, checked current V14 bindings and receipts, and read the longer logs without rerunning them. It did not approve the model's semantic output, a whole-company Result or real execution.

The remaining D03 work is substantial: bind complete authentic execution receipts for every required group; review subject, status, dates, conflicts and cross-group conclusions; implement and validate company Result/Run and public row; independently cold-read the full installed run; and separately obtain real-call/resource permission. A source-reference-valid recorded Candidate/Evidence cannot stand in for any of those gates. B13 remains suspended, D04's ten real private candidates are unchanged, and #47's branch, ledger and runtime roots were not touched.
