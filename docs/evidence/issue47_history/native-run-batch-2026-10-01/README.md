# 全帧批次：两份 SEC 批准取数之后的 50 个期间（2026-10-01）

## 跑了什么

第二份 SEC 批准（追加）取数完成后，五年框架的全部 50 个期间（10 家公司 × 5 年，`plan.tsv`）第一次都选得出期间、都有原件。每个期间一个工作进程、一个数据根，所有已接线指标，共 1,890 个位置。零 SEC、零模型调用。

- 代码：运行树是仓库提交 `877793e9` 加注册补丁。批次之后读运行树的快照，闭包就是每个 Run 记下的 `sha256:500ddf5f…`；运行树当时的清单保存为 `runtime-baseline-manifest.json`。
- 数据根：从获取导出恢复的根（`rt-restored/source-inputs`，请求日志 2,532 行），每个期间各装一份。
- 每个冻结的 Run 都由另一个进程冷读一次。

报告由 `report.py` 从批次自己的记录生成（`measured.json`），不手写数字。它沿用 09-30 批次的脚本，只补了这批新出现的失败类型和理由码；遇到没归类的理由码会停下，不会把它算进"缺口"。

## 结果

**尝试 1,890 个位置：1,832 个冻结并出公共行，另一进程冷读全部读到同一个 run 与 result；58 个失败。**

按 1,950 个目标位置（50 个期间 × 39 个指标）分层：

| 层 | 位置 | 说明 |
|---|---|---|
| 有值 | 882 | 872 个精确、10 个近似；其中 605 个已被独立阅读接受（按接受登记的当前内容） |
| 结构性不适用 | 795 | 指标对该公司不适用，这是答案 |
| 跑了没有值 | 155 | 15 个关于公司的答案、140 个按名扣留 |
| 没有结果 | 118 | 60 个路线未接线、10 个等 #28 采纳、48 个尝试失败 |

与 09-30 的 41 期间批次相比：期间 41 → 50，有值 641 → 882。

**跑了没有值的 155 个**：
- 15 个是关于公司的答案：分子非正 5、分母非正 4、接续主体不可比 4、首个年度不足一年 2。
- 44 个 E01 等模型确认（内容确认口径下，有候选条目的窗口在确认登记之前按名扣留）。
- 20 个是已命名的方法限制：B03 折旧范围未证明 6、C03 一年两个金额 6、C03 薪酬汇总表里一年两位首席执行官 3、C03 目标事实无效 3、B02 两年收入概念不可比 2。
- 76 个是已命名的来源或实现缺口：B06 来源关系 38、C04 审计师事实缺失 11、金融指标语义未解 12、Company Facts 6、全分支拒绝 3、accession 路线 3，B06 当期输入、C03 当期来源、E01 条目正文未定位各 1。

**没有结果的 118 个**：
- 60 个路线未接线：D03 的 50 个，B13 在范围内（Ford、Enphase）的 10 个。
- 10 个等 #28 采纳：最新年份的 D04（所有者选 A）。
- 48 个尝试失败：
  - 40 个是往年 D04 等模型审阅（具名停止）。
  - 5 个是 JPMorgan 的 B03：程序缺陷，批次之后修好（`../b03-bank-structural/`）。B03 只适用于非金融公司，计算器对银行给出了结构性不适用，但 D&A 范围检查只看"已发布"就运行，把它换成了"适用、扣留"，Run 存储据此拒绝。
  - JPMorgan FY2021 的 C02 与 C03：2022 年代理的封面把注册人名称印成一张 logo 图片，封面上没有文字名称（复选框也是 Wingdings 的 þ 与 o），封面身份检查按名停在 `HISTORICAL_PROXY_COVER_NAME_NOT_ESTABLISHED`。这是已命名的实现缺口，没有修。
  - Lumen FY2021 的 D02：Item 3 点名的小标题在被并入的附注里没有，路线按设计按名停下而不是整取附注。

**被已登记内容缺陷撤回的**：64 个位置，其中 59 个是有值的位置（C02 36、D02 13、D01 6、B03 2、C03 2）。

**没人读过的值**：218 个，几乎都在这批新选得出来的期间：JPMorgan 98、Salesforce 52、Southwest 29、Pfizer 21，以及 7 家公司往年的 C04。另有 3 个最新年份的 E01：已有接受读的是旧的条目规则计数，现在按内容确认口径算，规格、值和申报集合都变了，按设计不授予。

**两棵树**：仓库在 `877793e9` 的清单与运行树清单只差 12 个叶子，全在注册补丁的 6 个文件上；规则文件的叶子一个都不差。

## JPMorgan 往年的金融指标（初步）

JPMorgan 五个期间第一次都跑通。FY2025 的六个金融指标都有值；FY2021–FY2024 的 24 个位置里 12 个停在 `FINANCIAL_SOURCE_SEMANTICS_UNRESOLVED`。在恢复根上逐年直接问 #28 的冻结检查器：多数年份数字都读到了（例如 FY2022 的 LCR 1.12、净息差 2.0%、管理资产 2.766 万亿美元），停下的是"全发行人范围"的见证——检查器为最新年报的措辞写，往年的说法不同。A11（管理资产）四个往年都在这一步停下。逐个检查器读原文、判定是程序缺口还是披露差异，是下一步的工作，见剩余工作。

## 批次之后的变化与定向重跑

批次之后改变业务答案的代码只有两处：C02 选择器（共用修复 7–44，`../c02-selector-repairs/`）和 B03 的 D&A 范围条件。其余规则文件的改动只是路径与导入（C02 选择器换到 `_v3`，规格改名、字节不变），继承文件的改动是 #28 的普通路线。所以在新闭包下只定向重跑：50 个期间的 C02、JPMorgan 五年的 B03，以及 Paramount FY2025 的 B03（条件变了但答案应不变，顺带核对）。不改签本批次。
