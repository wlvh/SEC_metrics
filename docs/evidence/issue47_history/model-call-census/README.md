# 模型调用需求普查：往年的 D04、E01、D02（2026-09-30）

## 这是什么

在导出恢复的根上，对全帧批次能到达的 41 个期间（计划 `../period-batch/` 的 frame plan），用历史路线**自己的**请求构造函数把每个要模型审阅的请求建出来，并用钉定的参考分词器数 token（`census.py` → `census.json`）。零调用。最新年份的 D04 按所有者的选项 A 等 #28 采纳，不在这里建。代码是提交 `8997e8c5` 的 `scripts/`（其后到本记录只改了证据与文档）。

## 结果

| 指标 | 有请求的位置 | 请求数 | 参考输入 token | 全部放得进上下文 |
|---|---|---|---|---|
| D04（往年 32 个期间） | 32 | 335 | 55,065,497 | 是 |
| E01（事件窗口） | 34 | 34 | 186,897 | 是 |
| D02（Item 8 审阅） | 41 | 41 | 1,454,486 | 是 |

- 单个请求最大 195,777 个参考输入 token（Southwest FY2022 的 D04）。上下文上限是参考 token 加 4,096 输出预留不超过 200,000。
- D04 按公司：Ford 67 个请求 / 1,143 万 token，Pfizer 51 / 834 万，Lumen 51 / 805 万，Paramount 46 / 768 万，Enphase 36 / 603 万，Southwest 33 / 542 万，Macy's 24 / 384 万，Marriott 22 / 349 万，Salesforce 5 / 79 万。FY2021、FY2022 的请求数大致是 FY2023、FY2024 的两倍。
- 9 个最新年份 D04 位置等 #28 采纳，这里不建。
- E01 有 7 个窗口没有请求。Enphase 2022、2024、2025 三个窗口没有要确认的候选条目，这是路线的答案。Southwest 2021–2024 四个窗口是 `HISTORICAL_ZERO_AI_SOURCE_ROUTE_UNRESOLVED`，事件来源没解开：Southwest 的往年 8-K 在第一份 SEC 批准用满时只取了一部分，属于延伸批准的获取范围。
- 用上 D04 放宽单对象上限（`../d04-single-object-bound/`）的只有 Pfizer FY2022。

## 与已批的 35 个请求比

已批的 `[35,35,0]` 是 D04 16 个（Marriott FY2023/FY2024、Paramount 前身 FY2024）、E01 7 个、D02 12 个，合计参考输入 3,032,237 token。这次普查里这些位置的请求**数**与当时相同（D04 4、4、8），但摘要已随代码移动（见 `../d04-single-object-bound/`），批准正文要按新计量重新生成。

**往年 D04 的规模是已批总量的约 18 倍**（5,507 万对 303 万）。按 #28 的完整来源合同（每份年报的全部正文、原生事实与续接对象都要逐单元审一遍），一份年报是 4–28 个请求、56 万–431 万 token。

## 这对所有者意味着什么

这不是一个许可，也不改变已批的 35 个请求。要让往年 D04 进入五年框架，按现行合同需要另外按请求申请约 320 个请求。有两个方向，都需要所有者决定：

1. 按现行合同逐请求申请。可以先执行已批的 35 个，用实际结果与服务商报的用量校准，再决定是否扩展到其余 29 个期间。
2. 为往年 D04 另立更窄的请求合同，例如只审持续经营相关的章节。这会改变"完整来源审阅"的正确性标准，属于口径决定，要按修订机制对齐。

执行者的推荐是先做 1 的前半：先跑已批的 35 个，拿到真实结果和用量之后再定。E01（34 个）与 D02（41 个）的规模小两个数量级，可以在同一次申请里一起列出。

## 不主张

- 金额：这里只有 token，不换算成钱。
- 请求的内容是否正确、模型会怎么回答。
- 未到达的 9 个期间（JPMorgan 五年、Pfizer FY2021、Salesforce FY2022–FY2024 等要等延伸批准后的分片刷新）的需求；其中 JPMorgan FY2021/FY2022、Pfizer FY2021 的年报已量出含超过冻结单对象上限的续接对象。
- 这些摘要能直接放进批准正文：代码再改，摘要会动。
