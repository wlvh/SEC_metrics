# C02 往年：#28 的模型方法在三个历史位置上的开发验证（零调用）

#47 正文 v1.2 第 3.1 节要问的是：在别的年份和版式上，用模型读整份代理材料，是否比继续给规则选择器加规则更省。这里用 #28 的 C02 模型方法（`../../issue28_continuous/c02-model-input-pilot-20261003/`）在三个往年位置上做初测，与 #47 已有的两向判读逐块对照。**这是开发材料：回答出自同族开发上下文，不是 DeepSeek；没有调用，不给任何结果验收信用；C02 新用途不在已申请的 35 次之内。**

## 与 #28 对齐的输入和输出

- **输入**（`prepare_inputs.py`）：历史路线自己的治理文档（`tools/read_c02_composition.route_selection`，与 #28 的 `governance_source_document` 同一个文档构建），全部可见块按文档顺序标成 `[B<n>]`，块号就是 #47 两向判读用的块号。提示词用 #28 的 `prompt.txt`：只把开头一段换成本申报的发行人、表单、申报日、accession 与财年（#28 给 Paramount 也是这样改的），从 “Extract the registrant” 起逐字节相同（`task_sha256` 记在每个位置的 `metadata.json`）。请求体按 #28 的设置（deepseek-flash、temperature 0、输出上限 4096、JSON 对象）生成并用钉定的参考分词器计量，但不发送。
- **输出**：#28 的 JSON 格式（facts / unresolved，九种 kind），先过 #28 自己的机械检查 `postprocess.preview`（形状、类型、块号范围、完全重复、原文分组），再比对。
- 输入文件本身不提交（每份 40 万字左右），`inputs-index.json` 记下每个文件的摘要；在由已提交 SEC 导出恢复的数据根上重跑 `prepare_inputs.py`，应逐字节相同。

## 结论

1. **召回**：判读认定的事实，除股东提案人那一句（模型明确列为无法判定）外，模型在事实层面全部覆盖；块级的另外 4 个“漏选”是标签或已由别的引用覆盖。
2. **额外找到的事实**：8 个块按 #47 的口径是事实（其中 4 个有现成的裁定类），判读和规则选择器都没拿到。原因有两条，都是规则路线本身的：统一裁定的模式按某一份申报的原句写，换个写法就覆盖不到；阅读包按词汇取池，没写 “Committee” 的名片字段进不了池。
3. **不一致的大头是两份合同的约定冲突，不是模型错误**：任期字段 28 块、上下文块 6 块、资格认定含义 4 块。逐事实核对没有发现错误陈述。
4. **对照规则选择器**：49 处修复和 22 条裁定就是对着这三份判读写的，仍有 Ford 2 个漏选、Lumen 1 个误取 2 个漏选，并且同样漏掉第 2 条那 8 块；模型方法没有为这三份做任何调整。
5. **成本**：每个位置一次请求，参考输入 10.5 万–14.9 万 token，输出 2.2k–3.2k token；规则路线这边是 49 处修复、22 条裁定和随写法增长的维护量。

**实质修正没有使用**。剩下的不一致都在 #28 任务与 #47 裁定之间：任期字段算不算构成事实、陈述事实的块和上下文块在摘录里怎么区分（#28 的输出只有 `source_blocks`，块级验收会把上下文算误取）、提名理由算不算资格认定。单方面改提示会让 #47 的输入输出与 #28 分叉，而这三处都需要先对齐含义；所以这批按初测给出结果。

## 与 #28 对齐之后（2026-10-03，#28 在 #47 的评论 5968966522）

#28 回复了三处约定。按它的读法重看上面四个位置，不改提示、不重新作答：

- **上下文块**：#28 确认 `source_blocks` 是支撑一条事实的引用，不是“每块一条事实”；标题、姓名、日期、表头可以支撑同一条事实，不因被引用而多出事实；块级比较不能单独当作事实误取率。所以 Pfizer 的 6 个上下文块、Ford 的 3 个 “MEMBERS” 标签、JPMorgan 的 11 个上下文或过程句都是支撑，不算误取。
- **任期**：#28：与发行人自己的董事名片明确关联的 “Director since YYYY” 至少是成员关系的时间证据，不能当成本年度新加入；旁边的履历或别的组织的任期不能拼进来；一条独立的历史任期在最终构成输出里算不算，两份合同的写法还不完全一致，不为此新增 Spec。三份开发回答里的 28 个任期块和 JPMorgan 的 19 个，都是每位董事那条 `board_membership` 事实的时间证据（`stated_time` 写 “since 20xx”），没有一条单独的任期事实，也没有一条把年度之前的任期写成年度内加入。所以在事实层面它们不是误取。#47 的 `CARD_TENURE_FIELD` 管的是规则选择器按块取摘录，不改。
