# D01：跨页标题改为具名拒绝，不再合并（2026-10-02）

## 起因

#28 在复用本方 `historical_text_emphasis.py`（它固定读到 `2b4f571e`）时，由限定独审查出两处问题（[Issue #47 评论 5945148937](https://github.com/wlvh/SEC_metrics/issues/47#issuecomment-5945148937)；#28 的 `6425c239`、`865d8220`）：

1. **误合判据过宽**：两个标题之间只要夹着页码或带链接的目录行就合并，所以两个标题之间只有一个数字块 `1` 时也会合成一条。
2. **单跨度表示不成立**：合并后的标题用一个原始字节跨度记录（从前半段起点到后半段终点），而 TEXT_V1 的声明是"一个跨度的逐字摘录"。

#28 没有推断本方结果也有同样问题，请本方自己核对。普通路线的限制不能直接套到历史路线上，所以下面每一条都是在本方自己的运行证据上量的。

## 本方核对

- **表示问题在本方结果里成立。** 50 期间批次（闭包 `500ddf5f`）里，合并只发生在 Southwest FY2022（第 524、636 块）和 FY2023（第 562 块）。读这两个 Run 自己的候选记录：每个合并标题记录的原始跨度解码后是"… adverse weather or **36 Table of Contents** a localized disaster …"，声明文字不是该跨度的原文。本方证据检查（`historical_risk_results.build_text_evidence`）只比对声明文字与块的强调字段，并对跨度取哈希，两项都通过，所以没有发现。
- **误合判据在本方是潜在缺陷。** 本方规则与 #28 复制的是同一份，同样过宽；但 50 份申报里每一处合并都同时夹着页码和带链接的目录行（`measured-before.json` 的 `joins_without_the_contents_link` 为空），单个数字的情形没有出现过。

## 处置

移植 `865d8220` 的做法：删去合并；`split_heading_requires_multispan` 只认一种版式——不以句末标点结束的整块强调标题、页码、带链接的"Table of Contents"行、以小写开头的整块强调续句，四块相邻——遇到就以 `D01_MULTISPAN_HEADING_UNSUPPORTED` 拒绝整份文档。这是实现缺口，不是没有披露：申报写了这个标题，本路线还不能把一个标题表示成两个跨度。其他版式按冻结解析器原样处理；单个数字夹在两个标题之间仍是两个标题。

## 量测（零调用）

- `measure_before.py` → `measured-before.json`：移植前，50 份 D01 申报里哪里合并、合并处夹着什么。
- `measure_after.py` → `measured-after.json`：移植后逐份重建。**48 份申报重建出的文档与候选，与批次 Run 记录的逐字节相同**；Southwest FY2022、FY2023 以 `D01_MULTISPAN_HEADING_UNSUPPORTED` 拒绝。

## 对结果的影响

Southwest FY2022、FY2023 的两个合并结果（`758ecf62…`、`b6ad4937…`，在闭包 `500ddf5f` 与 `e667d42c` 下编号相同）按坐标登记缺陷撤回：`D01_SOUTHWEST_2022_JOINED_HEADING_SPAN_IS_NOT_ITS_TEXT`、`D01_SOUTHWEST_2023_JOINED_HEADING_SPAN_IS_NOT_ITS_TEXT`。它们的标题文字已被独立阅读判对（接受条目仍在），撤回的是证据记录；撤回优先于接受。移植后这两个位置没有结果，所以没有可释放的对象；两条旧缺陷（"半截标题各成一行"）的释放仍然成立，旧条目里加了 `later` 说明。

## 验证

- `tests/vnext/test_historical_page_split_headings.py`（19 例）：两份真实年报按名拒绝；版式正好落在批次合并过的那三处；跨两半的一个跨度里确实夹着页码和目录行；不拒绝时冻结选择器会把半截列成行；路线候选按名拒绝；Southwest FY2025、Enphase FY2025（页脚分类标签接下一页标题，是两个标题）重建出批次的文档；构造块逐条守版式的每个条件，包括 #28 独审的"只有一个数字"反例；构造整份年报走通构建器。
- `injections.py` → `injections.json`：7 个注错，每个去掉版式的一个条件或整个拒绝。

## 没做的

- 多跨度表示：要接受跨页标题，需要新的摘录合同（一个标题记录两段原文，各自定位、各自审阅），并先与 #28 对齐，不在本次。
- 其他分页版式（只有页码、目录行在页码前等）：不拒绝也不合并，按冻结解析器处理，可能把半截列成两行。独立阅读工具 `tools/read_d01_headings.py` 对任何"标题只隔页面装饰又接一行标题"的两行都要求记录判断，所以这类情况在阅读层会被看到。
