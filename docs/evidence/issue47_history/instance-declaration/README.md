# 往年 C04 与 B06 缺的 XBRL 实例文件：声明缺口（2026-09-30）

## 问题

全帧批次里往年的 C04（32 个位置）与 B06 FY2021–FY2023（23 个位置）都按名扣留"来源未解"，批次记录里没有写缺什么。在导出恢复的根上直接问路线（`probe.py`）：两者停在同一个文件——年报 accession 的 XBRL 实例（`*_htm.xml`），例如 Enphase FY2023 的 `enph-20231231_htm.xml`；Marriott FY2024 的 C04 停在上一年 accession 的实例。

冻结的治理读取器 `auditor_filing` 读 accession 的 `index.json`，再读它列出的每个 XBRL 实例（主文件已存也要读）；C04 为目标年与上一年各读一次，B06 的级联为目标年读同一个读取器。规划器每个年报 accession 只声明主文件与 `index.json`，所以第一次获取取回了往年的主文件与索引、一个实例都没取；获取门禁也会把这些文件当作"未声明的依赖"拒绝。**这是声明缺口，不是披露缺失**，而且现有的延伸申请也解不开它。

## 改动

`scripts/vnext/historical_instance_sources.py`（不是规则文件，理由与事件、治理声明相同：规划器是规则文件）用一个"只记录、不读取"的读取器跑冻结的 `auditor_filing`，所以列表就是冻结读取器自己的过滤结果，不是抄一份过滤规则。并入声明框架；类别 `ACCESSION_XBRL_INSTANCE` 属于"取回后不会让新东西可声明"的终态类别；接线收据重建（安装前 204 例、针对候选 10 例）。索引没存的 accession 记为具名限制，不记为空集。

## 用例与注错

`tests/vnext/test_historical_instance_sources.py`（6 例，约 52 秒，saved-source 层）：Marriott 最新两年的实例已存，声明必须等于冻结读取器真实读到的 XML 文件；声明模块单独问时只列实例（经帧合并时规划器的行会胜出，会掩盖多列主文件的错误——第一次注错运行正是这样漏掉的）；索引未存记为限制；读取器不读的同级文件（`_cal.xml`）不算声明依赖；类别是终态。`injections.py` → `injections.json`：4 个全部由为它写的用例抓到。第一次运行漏了一个（`injections-first-version.json`）：让声明模块把主文件也记成实例，经帧合并后规划器的行胜出，用例看不见；补了一条直接问模块本身的用例后抓到。
