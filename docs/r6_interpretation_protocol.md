# D04 离线解释协议

当前原型准备完整解释输入，并检查保存的响应是否完整、引用是否准确、分类字段是否一致。它没有调用模型，没有验证判断正确性，也没有生成 D04 原生 Run 或正式结果。预算和独立审阅仍待落实；这里的请求是内部草案，尚未形成获准发送的 DeepSeek 调用。

## 输入和响应

`r6_semantic_source.prepare_d04_semantic_source(repo_root=..., company_id=...)` 从既有可信保存来源读取原年报和同年度全部修订。全部可见块、原生事实、所引用的原生上下文/单位及续接、脚注、关系对象进入输入。原生事实不按关键词筛掉；原命名空间、属性、原文和引用关系保留。嵌套 XML 只保存外层一份，逐项证明内部位置能恢复原始子对象。可见文本的 HTML 引用容器由程序标记。

普通单元上限为 150,000 字节，单个完整对象最多 300,000 字节，每个请求的来源部分最多 450,000 字节。对象不会被截断；这些是输入组织的字节边界，不是实测模型 token 数或可行性证明。模型处理这些输入的可靠性仍须真实验证。

`r6_semantic_review.requests_from_source(source)` 生成内部请求草案。财年使用普通输入 v2 的已证明标签，同时提供原始标签和冲突状态。模型只需返回来源索引及准确引文；程序查找唯一匹配并计算字符位置，不要求模型数偏移量。

`inspect_recorded_responses(repo_root=..., company_id=..., response_bytes_by_request_id=...)` 重新读取真实保存来源，核对完整请求集合，再处理调用者提供的响应字节。检查包括：

- 请求与单元的内容身份一致，每个单元恰好回复一次。
- 已发现的疑虑语言/原生概念候选有明确分类，不能在空结果中丢掉。
- 引文存在于给定来源对象且唯一，空白、错文、错索引和超限引用被拒绝。
- 当前目标主体、历史、其他实体、条件性陈述的枚举关系不矛盾；引用容器中的文字不能单独充当当前主体断言。
- 相互冲突的当前分类保留合并层面的未解决原因，不按优先级强行选出一个结论。

返回值是 `D04_RECORDED_INTERPRETATION_CANDIDATE`。`model_proposed_interpretation` 只是响应提出的分类；`semantic_correctness_verified`、`semantic_qualification_passed`、`provider_execution_proven` 和 `native_result_created` 均为 false。`all_source_units_responded=true` 只说明响应集合完整。

## 实际验证

十家公司、12 份文件、28,415 条原生事实均已完成输入组织和重建核对。第一轮 Ford、Pfizer、JPM 的完整续接对象超过 150k 单元边界；保留原失败后，以单对象 300k 上限解决，没有拆断对象。嵌套去重使请求草案从 176 份降到 161 份，来源载荷从 66,195,014 降到 59,821,661 字节。

```bash
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=scripts python3 -m unittest -v tests.vnext.test_r6_semantic_review
```

测试采用 Enphase 的实际供应商/合作伙伴文字作为可检查的协议样例，响应由测试程序提供。覆盖缺请求/单元、遗漏候选、错误或重复引用、主体/时间冲突、引用容器、跨单元冲突及非法类型。测试程序生成的“未披露”提议不算一次真实模型判断。已有输入、较早协议版本和当前响应规则的证据分开记录。

## 后续接线

在获批预算下，先有限验证模型是否能可靠解释这些真实来源及关键反例，再接入既有 provider 调用记录、Evidence、Review、原生文本结果和普通运行入口。不能通过把原文打包完整、响应 JSON 合法或干净审计意见，当作“未披露持续经营疑虑”的充分证明。D03 仍需完成自己的段落判断，B13 和其余完整交付责任不因本原型完成而结束。
